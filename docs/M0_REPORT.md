## 측정 방법

React/Pixi에 연결된 동일한 `SimulationEngine`을 Node.js에서 직접 실행했다. 모든 측정은 정해진 초기 설정만 사용하며, 실행 도중 개체·자원·에너지·사건을 주입하지 않는다. 생태계가 멸종해도 20,000틱까지 자원 재생과 시간 흐름을 계속 측정한다. UI는 멸종 시 자동 일시정지하므로, 멸종 후 자원 회복 구간은 UI에서 자동 진행되는 구간이 아니다.

- 초기 50개체, 시드 2026 / 42 / 99, 균형 / 숲 / 건조의 9개 조합.
- 별도로 기존 100개체 스트레스 테스트 관측을 재현했다.
- 매 틱 개체 수·자원량·평균 에너지·누적 탄생/사망·번식·사망 원인·실제 소비/재생량 기록.
- 1,000틱 구간별 출생·사망 및 개체 노출 시간(organism-ticks) 대비 사망률 계산.
- 매 틱 `누적 탄생 - 누적 사망 = 생존 개체` 및 자원 수지 오차 < 0.000001 검증.
- 누적 탄생에는 최초 배치가 포함된다. 번식으로 태어난 자손 수는 누적 탄생에서 초기 개체 수를 뺀 값이다.

측정 스크립트: [qa-m0-ecology.mjs](../scripts/qa-m0-ecology.mjs). 원본 데이터는 [조정 전 JSON](qa/m0/ecology-results.json), [조정 후 JSON](qa/m0/tuned/ecology-results.json), 각 디렉터리의 매 틱 CSV와 개별 사망 JSON이다. 결과 JSON에는 규칙, 소스 해시, 실행 시간, 재현 해시도 기록되어 있다.

## 기존 139 → 0 결과의 원인

이 결과는 **초기 50개체가 아니라 100개체** 조건에서 정확히 재현됐다.

- 시드 2026, 균형 맵, 목표 먹이 최소량 0.01.
- 319틱에 최대 139개체, 1,532틱에 전멸.
- 초기 100 + 자손 41 = 누적 탄생 141, 누적 사망 141.
- 에너지 고갈 141, 노화 0. 최대 수명 2,400틱 전에 모두 사망했다.
- 초기 자원 9,338.94, 최소 자원 7,729.53. 세계 전체 먹이가 소진된 전멸은 아니었다.
- 141마리 중 132마리는 사망 위치의 감지 반경에 양이 0.01 이상인 먹이가 있었다. 단, 이 개수에는 미량 재생된 먹이도 포함되므로 충분한 먹이에 도달할 수 있었다는 뜻으로 해석하면 안 된다.
- 개별 사례 #109는 섭취 중 사망했으며, 감지 반경에 먹이 65.92가 남아 있고 직선 이동 경로를 통과할 수 있는 자원 패치가 4개 있었다.

원인은 가까운 패치의 **잔량을 거의 고려하지 않는 목표 선택 규칙**이었다. 패치가 고갈된 뒤에도 0.01만 재생되면 다시 목표가 된다. 평원의 고갈 패치는 틱당 약 0.006을 재생하고, 이를 전부 먹어도 약 0.0114E이다. 성체 유지비 0.07~0.13E/틱보다 적어 제자리에 있거나 근처를 왕복하면서 에너지가 감소한다. 가까운 미량 패치가 더 멀리 있는 충분한 먹이로 이동하는 것을 방해한다. 기하학적 장애물과 유한 감지 반경도 일부 개체의 먹이 접근을 제한한다.

100개체 대조군에서 0~1,000틱에는 자손 41, 사망 95가 발생했다. 1,000~2,000틱에는 자손 0, 사망 46이었다. 사망률은 각각 **1,000 organism-ticks당 0.882 → 5.315**로 상승했다. 멸종 뒤 자원은 20,000틱에 전체 용량 13,200까지 회복됐지만 새 생명체는 생성되지 않았다.

## 변경한 설정과 변경 이유

유일한 생태계 규칙 조정은 `SimulationConfig.minimumFoodAmount` **0.01 → 0.5**이다. `ResourceSystem`은 이 값보다 적은 패치를 목표에서 잠시 제외해 자원이 쌓이도록 한다. 여전히 감지 범위 안에서 가장 가까운 유효 패치를 선택하며, 인공적인 번식/생존 보정은 없다.

변경하지 않은 항목: 초기 에너지, 기초/이동 비용, 재생률, 번식 비용·수명·대기시간, 최대 개체 수. 리스폰, 최소 개체 수 유지, 사망 방지, 환경에 따른 강제 결과 연출을 추가하지 않았다.

0.5는 한 번에 최대 0.95E를 제공하는 작은 섭취량이다. 충분한 양을 확보한 패치 사이에서 이동하도록 해 미량 재생분만 반복 수확하는 문제를 줄인다. 이 값이 모든 시드에 최적이라는 결론은 내리지 않는다.

## 폭증·급감·실행 안정성의 해석

- 조정 후 50개체 실험의 정점은 80~150이며 최대 개체 제한 512에 도달한 틱은 모든 조건에서 **0**이었다. 제한에 의존해 폭증을 막은 결과는 아니다.
- 균형 시드 2026·42는 1,000틱 구간에 66개체 감소했다. 건조 조건은 빠른 감소 뒤 실제 전멸했다. 이런 변동을 숨기거나 평탄화하지 않았다.
- 조정 후 별도의 기존 100개체 장기 회귀 테스트는 20,000틱, 정점 160, 최종 35, 탄생 768 / 사망 733으로 통과했다.
- 모든 장기 실행이 정상 종료했고 자원 수지·개체 계수·시드 재현 검증을 통과했다.
- 기존 100개체 자동화 테스트는 이벤트 80 / 사망 기록 20 / 시계열 30의 작은 보관 한도도 매 틱 검사했다. 기본 설정 실측에서는 최종 보관 2,000 / 256 / 600이었다.
- 측정 프로세스의 힙에는 매 틱 CSV 행과 개별 사망 자료를 모으는 분석기 자체의 증가분이 포함된다. 이를 엔진 단독 메모리 누수 벤치마크나 브라우저 메모리 안정성 입증으로 주장하지 않는다.
- 3개 시드 × 3개 환경의 유한한 실험이다. 모든 시드·무한 시간 생존 또는 기기별 FPS를 보장하지 않는다. 지형을 돌아가는 탐색은 단순 규칙이므로 경로 찾기 성능의 한계도 남는다.

별도 CMD에서:

```cmd
node scripts/qa-m0-browser.mjs
```

장기 분석 재현:

```cmd
node --expose-gc scripts/qa-m0-ecology.mjs
node --expose-gc scripts/qa-m0-ecology.mjs --tuned
```

두 명령은 각각 최소 먹이량 0.01 / 0.5를 명시하므로 현재 기본값 변경 뒤에도 비교를 재현할 수 있다. 원본 CSV를 재생성하므로 기존 측정본을 별도로 보존하려면 실행 전에 복사한다.

M1에서는 신체 유전형/표현형의 구분, 기관별 비용, 돌연변이 검증 및 계통 기록 정책을 먼저 설계한다. M0에 변이·신경망·학습·사회·문명을 미리 추가하지 않았다. M0 완료 확인과 함께 사용자가 GitHub 커밋·푸시를 요청했다.
